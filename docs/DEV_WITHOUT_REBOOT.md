# Разработка драйверов без перезагрузок: связь с Windows по Bluetooth

Раньше каждый тест требовал цикла «положить файлы → перезагрузить → прочитать результат», что занимало минут восемь и ломалось на грязной NTFS.
Теперь Windows держит связь с компьютером разработчика по Bluetooth SPP. Команды выполняются прямо в Windows, файлы передаются с проверкой.

## Состав
| Файл | Где работает | Назначение |
|---|---|---|
| `windrv/agent/btagent.ps1` | Windows (планшет) | агент: принимает строки по COM-порту Bluetooth SPP: `PING`, `CMD`, `PS`, `PUT`, `PUTA`, `GET`, `BYE`, `RESTART` |
| `windrv/agent/btwatch.ps1` | Windows (планшет) | сторож: запускает агент, следит за пульсом и перезапускает его |
| `windrv/agent/agent_main.cmd` | Windows (планшет) | при наличии `C:\j606f\btmode` запускает сторожа вместо старого агента |
| `scripts/btsh.py` | компьютер разработчика | клиент: демон и команды `ping`, `restart`, `cmd`, `ps`, `put`, `get` |
| `scripts/pi_btbridge.py` | одноплатный компьютер с BlueZ | мост: SPP-сервер (канал 22) ↔ TCP на `127.0.0.1:7106` |

Сеть не используется: мост слушает только loopback, компьютер разработчика подключается к нему через туннель SSH.

## Как устроен путь
Планшет (Windows) ⇄ Bluetooth SPP ⇄ одноплатный компьютер (`pi_btbridge.py`) ⇄ туннель SSH ⇄ компьютер разработчика (`btsh.py`).

- Исходящий COM-порт Windows подключается к SPP-сервису моста. Сообщения — строки с LF; файлы передаются base64.
- `btsh.py put` отправляет большие файлы кусками по 256 КиБ с повтором потерянного куска. Файлы проверяются по sha256.
- Агент пишет журнал команд в `C:\j606f\out\btagent.txt` (без вывода команд) и пульс в `btagent.hb`.
- Команды `CMD` и `PS` выполняются в дочернем процессе с пределом времени (по умолчанию 600 с; можно задать `CMDT <с>` / `PST <с>`),
  поэтому зависшая команда не блокирует агент.

## Постоянный режим
1. На планшете создать `C:\j606f\btmode`. Тогда `agent_main.cmd` запускает `btwatch.ps1`, а тот — `btagent.ps1`.
2. Загрузочное значение по умолчанию (`j606fboot.def`) — `0` (Windows). После сбоя или перезагрузки планшет сам возвращается в Windows
   с работающим агентом. Меню при этом не нужно.
3. Если пульс пропал на 180 секунд, сторож перезапускает агент. Если связь не восстановилась три раза подряд, при наличии файла
   `C:\j606f\btwatch.reboot` сторож перезагружает Windows. Пока связи не было с момента загрузки, перезагрузок не делается, чтобы не
   возникло петли.

## Команды на компьютере разработчика
```sh
python3 scripts/btsh.py daemon                  # держит порт Bluetooth открытым (Windows подключается к нему)
python3 scripts/btsh.py ping                    # проверка связи
python3 scripts/btsh.py cmd "ver"               # командная строка на планшете
python3 scripts/btsh.py cmd -t 60 "<команда>"   # с пределом времени 60 с
python3 scripts/btsh.py ps "Get-ChildItem C:\j606f"
python3 scripts/btsh.py put локальный.sys C:\j606f\drv\файл.sys
python3 scripts/btsh.py get C:\j606f\out\btagent.txt локальный.txt
python3 scripts/btsh.py restart                 # перезапуск агента на планшете (после обновления агента)
```
Переменные окружения: `J606F_TCP` — адрес моста (например, `127.0.0.1:7106` при туннеле SSH); `J606F_TTY` — локальный порт Bluetooth,
если отличается от значения по умолчанию.

## Мост на одноплатном компьютере
1. Требуются BlueZ, `python3-dbus`, `python3-gi`; пользователь в группе `bluetooth`; адаптер не заблокирован rfkill. Root не нужен.
2. Запуск: `python3 pi_btbridge.py`. Для первого сопряжения: `python3 pi_btbridge.py --pair 180` (открыто 180 секунд; сопряжение
   подтверждается автоматически только в этом окне).
3. С компьютера разработчика: `ssh -N -L 127.0.0.1:7106:127.0.0.1:7106 <пользователь>@<адрес моста>`, затем `J606F_TCP=127.0.0.1:7106 python3 scripts/btsh.py daemon`.
4. Автозапуска моста в этом репозитории нет: его включают вручную, по решению владельца.

## Осторожность
- **Адреса Bluetooth (BD_ADDR, MAC) и адреса сетей не записываются** ни в журналы, ни в публичные файлы.
- Команды на планшете выполняются с правами агента (LocalSystem). Не отправляйте команды, которые меняют разделы модема или
  загрузчики Lenovo: это запрещено правилами проекта.
- Для перезапуска агента после обновления файла используйте `restart` или `put` с последующей перезагрузкой только если файл занят.
- Если связи нет больше 10 минут, проверьте журнал моста и при необходимости перезапустите его; агент сам переподключается.
