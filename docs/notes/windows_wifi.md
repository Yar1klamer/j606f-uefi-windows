# Wi-Fi в Windows на J606F: разведка и план

Статус: **не работает.** Документ фиксирует, как Wi-Fi устроен на этом чипе и какие шаги нужны. Пока сделан только запуск ADSP
(см. [windows_adsp.md](windows_adsp.md)).

## Как Wi-Fi работает в Linux (pmOS: сканирование, WPA2, DHCP и интернет работают)
WLAN-часть WCN3990 управляется не процессором приложений напрямую, а прошивкой на модеме (MPSS). Цепочка такая:
1. **MPSS** (`modem.mbn`, PAS id 4) запускается через remoteproc. Внутри работает WLAN-процесс (user-PD `wlan_process`).
2. **rmtfs** — служба процессора приложений для EFS модема. Модем по QMI просит читать и писать `modemst1`, `modemst2`, `fsg`, `fsc`
   через общую память `0x89B01000`. В pmOS она работала на **копиях в оперативной памяти**; разделы модема на запись не трогаются.
3. **tqftpserv** — TFTP поверх QRTR: модем скачивает `wlanmdsp.mbn`. Этот образ должен совпадать с `modem_a` данного планшета, иначе
   модем перезапускается по таймеру `wlan_process`.
4. **qrtr-ns и pd-mapper** — служба имён QRTR и карта доменов (servreg): модем запрашивает, какой домен где работает.
5. **ath10k_snoc** — драйвер WLAN. Использует QMI WLFW (адрес MSA `0x51900000`, режим, board data), затем HTC/WMI через copy engine
   (MMIO `0x0C800000`, 12 прерываний SPI 358–369), данные идут через HTT. Чип: chip_id `0x150`. Board data берётся из linux-firmware
   и подходит к устройству.

## Что из этого нужно в Windows
| Шаг | Что делать | Объём |
|---|---|---|
| A. Запуск MPSS | тот же путь, что у ADSP (таблица `g_mpss` в btbus) | готов к проверке |
| B. GLINK через SMEM к модему | транспорт сообщений (FIFO в SMEM, элементы 478/479/480 для пары APPS/модем) и пинок APCS бит 12 | средний; общий с ADSP (звук) |
| C. QRTR и QMI | маршрутизация QRTR, служба имён, кодирование QMI TLV | средний |
| D. rmtfs (только оперативная память) | образы `modemst1`, `modemst2`, `fsg`, `fsc` читаются из разделов только на чтение; записи модема — в копию в памяти | средний; запись во флеш не делается |
| E. TFTP и pd-mapper | отдать `wlanmdsp.mbn`, ответить на servreg | малый–средний |
| F. WLFW QMI, CE, HTC/WMI | поднять прошивку WLAN, сканирование | большой |
| G. Сетевой драйвер Windows | NDIS-минипорт (сначала как Ethernet и свой supplicant, либо WDI/Native Wi-Fi) | очень большой |

Реалистичная оценка: шаги A–E — инфраструктура удалённых процессоров (она же нужна звуку и датчикам). F даёт первое «сеть видна из Windows».
G — подключение к сети в Windows. Сроки: дни на A–E, недели на F–G.

## Прошивки и данные
- `modem.mbn` собирается из раздела `modem_a` этого планшета (FAT16, только чтение). `wlanmdsp.mbn` — тоже из `modem_a`.
- Board data — из linux-firmware (ath10k, WCN3990, hw1.0).
- Все эти файлы — блобы Lenovo/Qualcomm, в репозитории их нет.

## Ограничения и риски
- Модем без rmtfs не может писать EFS вообще: запись во флеш делает только сторона процессора приложений через rmtfs. Поэтому
  сам запуск MPSS ничего не записывает.
- rmtfs в Windows — только поверх копий в оперативной памяти. Настоящие `modemst*` и `fsg` не меняются: это жёсткое правило проекта.
- MAC-адрес Wi-Fi в публичные материалы не попадает.
