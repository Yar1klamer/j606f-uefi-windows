# ADSP и модем из Windows: запуск удалённых процессоров своим кодом

## Итог
- **ADSP (LPASS Q6, PAS id 1) запущен из Windows.** TrustZone принял образ, ADSP ответил по SMP2P значением `slave-kernel = 6` (READY + HANDOVER).
- Код: `windrv/btbus/adsp.inc`, входит в драйвер `btbus.sys`, где уже есть канал RPM GLINK, доступ к MMIO и журнал. Таблица `RPROC`
  общая для ADSP и MPSS (модема).
- Запуск одноразовый, по флагу `C:\j606f\drv\adsp.arm` (для модема — `mpss.arm`). Флаг открывается с удалением при закрытии, поэтому сбой
  не повторяется при следующей загрузке.
- Прошивки `adsp.mbn` и `modem.mbn` — блобы Lenovo с этого планшета. В репозитории их нет.
- Пишется только оперативная память: зарезервированная область процессора и общая память SMEM. Флеш не трогается.

## Последовательность
Порядок повторяет Linux: `qcom_q6v5_pas`, `qcom_mdt_loader`, `qcom_smp2p`, `qcom_smem`.
1. **SMEM** (0x46000000, 2 МиБ). Читается только таблица разделов (последние 4 КиБ) и раздел APPS/ADSP. Сплошное чтение всех 2 МиБ
   перезагружало SoC, поэтому его больше не делаем.
2. **Исходящий SMP2P** (APPS → удалённый процессор). Элемент выделяется в разделе так же, как `qcom_smem_alloc_private()`: под аппаратной
   блокировкой hwspinlock 3 (мьютекс TCSR), с канарейкой `0xa5a5`, номером элемента и размером; затем сдвигается `offset_free_uncached`.
   В элементе `$SMP`, версия 1 (записывается последней), признак SSR_ACK, записи `master-kernel = 0`. Пинок — регистр APCS, бит из DT.
3. **Голоса RPM** (как proxy-голоса Linux): уровни питания (`swen` 1, `vlvl` 416 = TURBO_NO_CPR), голос крипто-шины, частота CE 192 МГц.
4. **Метаданные образа.** ELF-заголовок, phdr (размер `phdr[0].p_filesz`) и хеш-сегмент копируются в физически непрерывную некэшируемую
   память ниже 4 ГиБ.
5. **Вызовы SCM** (SMC64, std call, SIP): `x0 = 0x42000200 | команда`.
   `PAS_INIT_IMAGE` (1; id и физический адрес метаданных) → `PAS_MEM_SETUP` (2; id, база, размер) → копирование сегментов в
   область процессора (`p_paddr − min_paddr`; хвост `memsz > filesz` заполняется нулями) → `PAS_AUTH_AND_RESET` (5).
   При ошибке вызывается `PAS_SHUTDOWN` (6).
6. **Опрос входящего SMP2P.** Согласуются версия и признаки, подтверждается SSR, затем ждём биты READY (1) и HANDOVER (2) в записи `slave-kernel`.

## Главная ловушка: продолжение прерванного вызова TrustZone
TrustZone возвращает `x0 = 1` (`QCOM_SCM_INTERRUPTED`), если пришло прерывание. Продолжать вызов нужно с `x0 = 1` и **`x6`, равным
значению `x6` из ответа TZ**. В Linux это `ARM_SMCCC_QUIRK_QCOM_A6` в `__scm_smc_do_quirk`. Если передавать `x6 = 0`, процессор застревает
в TZ, и Windows падает с BSOD `0x101 CLOCK_WATCHDOG_TIMEOUT`.
С правильным `x6` инициализация образа занимает около 26 мс (1–3 продолжения), `auth_and_reset` около 138 мс (12–14 продолжений).

Проверенные ложные причины: таймер 1 мс (его держит `hidtouch`, поэтому есть флаг `C:\j606f\drv\timer.slow`) и голоса крипто-шины.

## Параметры (DT sm6115.dtsi и qcom_q6v5_pas.c)
| | ADSP | MPSS (модем, нужен для Wi-Fi) |
|---|---|---|
| PAS id | 1 | 4 |
| область процессора | 0x53800000 + 0x2800000 | 0x4AB00000 + 0x6900000 |
| раздел SMEM | хосты 0/2 | хосты 0/1 |
| SMP2P вход / выход | 443 / 429 | 435 / 428 |
| бит пинка APCS | 10 | 14 |
| proxy-голоса | LPI_CX `rwlc`, LPI_MX `rwlm` | CX `rwcx` |
| причина сбоя в SMEM | 423 | 421 |
| GLINK | SPI 277, бит APCS 8 | SPI 68, бит APCS 12 |

Области в карте памяти UEFI v7 зарезервированы: PIL Reserved (0x4AB00000 + 0x9400000), pmOS PIL (0x53F00000), pmOS Rsvd (0x89B01000).

## Что дальше
- Снимать proxy-голоса после HANDOVER: сейчас они держатся до перезагрузки.
- GLINK через SMEM к ADSP (элементы 478, 479, 480) → QRTR → QMI. GLINK и QRTR к модему уже работают (Wi-Fi): см. [windows_wifi.md](windows_wifi.md). Для звука и датчиков нужен GLINK к ADSP.
